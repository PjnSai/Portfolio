# OWASP Top 10 (2025) map

Each item maps to the control that covers it and the automated test that proves it. A row is **done** only when both exist and the test runs in CI. The 2021 list maps onto the same controls.

Status after phase 2A. "Phase 2A done" means the admin, auth and content-backbone part of the item is covered; later phases add the parts named in the row.

| Item | Control | Test | Status |
|------|---------|------|--------|
| A01 Broken Access Control | API denies by default; Django admin not installed. Every URL under `/api/v1/admin/` goes through one check (`core/authz.py`) with a declared level: Access only, session, or fresh passkey confirmation. A route with no level is refused. Cloudflare Access token checked on every admin request, before the URL is resolved, with the owner email compared exactly. One owner row in the database; the app login cannot add or remove it and no route creates an account. CSRF token on every state-changing session route, plus exact Origin and `Sec-Fetch-Site`. Random UUID keys. Content routes (sections, items, publish, versions, trash) need a session and are picked up by the route tests automatically; permanent delete only through the vital action, and only from the trash. Admin pages at `/desk` are `noindex`, `no-store` and not linked from the public site. The web service forwards only an allow-list of headers to the API. | `test_routes.py` (every admin route, including the content routes, with no, wrong, expired, revoked and correct session; elevation), `test_content.py`, `test_vital.py` (trash-first permanent delete), `web/tests/api-proxy.test.ts`, `web/tests/security-headers.test.ts` (admin headers), `web/e2e/admin.spec.ts`, `test_csrf.py` (every route in the API with every state-changing method), `test_guard.py` (Access token, origin checks), `test_status.py`, `test_models.py` (UUID keys), `test_owner.py` (single owner, exact Access email), `test_db_roles.py` (owner and content grants). | Phase 2A done |
| A02 Security Misconfiguration | Debug off unless explicitly enabled; start-up refused without a secret key; admin refused if Access or the site origin is not configured. API headers defined once in `core/headers.py` (deny-all CSP, HSTS, `nosniff`, frame denial, no referrer). Web headers defined once in `web/lib/security-headers.ts` and applied by `web/proxy.ts`: nonce CSP with no `unsafe-inline` or `unsafe-eval`. Non-root read-only containers. Image hardening: phase 6. | `test_headers.py`, `test_status.py`, `test_guard.py` (missing configuration), `web/tests/security-headers.test.ts`, `web/e2e/csp.spec.ts` (nonce per request, inline script blocked in a real browser). | Phase 1 done |
| A03 Software Supply Chain Failures | npm lockfile, pip installs with hashes, actions pinned to commit hashes, `npm audit`, `pip-audit`, Dependabot, CodeQL. SBOM, image scan, provenance: phase 6. | CI jobs `web`, `api`, `images`; CodeQL workflow. | Started |
| A04 Cryptographic Failures | No passwords anywhere: passkeys only, public key stored. Session token is 256 random bits and only its SHA-256 is stored. Cookie is `__Host-`, `Secure`, `HttpOnly`, `SameSite=Strict`. Audit chain and rate-limit keys use HMAC-SHA-256 with keys from the environment. Access tokens accepted as RS256 only. HSTS on both services. TLS and Secret Manager: phase 7. | `test_sessions.py` (cookie flags, token size, hash only), `test_login.py` (public key material only), `test_guard.py` (unsigned and wrongly signed tokens), `test_audit.py` (rehash without the key is detected), `test_models.py` (no password table). | Phase 1 done |
| A05 Injection | ORM only; CI and a test fail on `raw()`, `extra()` and direct cursors. Query and body fields are validated against fixed patterns and allow-lists before use. Content bodies go through strict DRF serializers: unknown fields refused (mass assignment), types and lengths enforced, control characters refused, links `https` only. Text is stored as typed and escaped by React in the admin. Sanitised Markdown on the public site: phase 3. | `test_injection.py` (SQL payloads in query, path, cookie, headers and bodies; no hand-written SQL), `test_audit_routes.py` (bad query refused), `test_content_validation.py` (every field, mass assignment, bad JSON, bad paging), CI step "No raw SQL". | Phase 2A done |
| A06 Insecure Design | Threat model kept current; security tests written before the code. Vital actions (adding a passkey, permanent deletion) need a fresh passkey confirmation, a fixed 24-hour wait, a notice to the owner and a second confirmation; a session alone can cancel but never run one. Undo instead of warnings: trash with 30-day restore, and version history with restore. Caps on sections and items. Admin fails closed. Public pages fail static: phase 3. | `test_vital.py`, `test_notify.py`, `test_fail_closed.py`, `test_content.py` (trash, restore, purge, caps), `web/e2e/admin.spec.ts` (vital action with cancel), `docs/THREAT-MODEL.md` review in the release checklist. | Phase 2A done |
| A07 Authentication Failures | Passkey (user verification required) behind Cloudflare Access. Single-use challenges bound to their purpose and session. Server-side sessions: new token at sign-in and at every privilege change, 15-minute idle and 8-hour absolute timeout, revoke-all. Every failed sign-in costs the same work and returns the same answer. Cool-down after repeated failures per client; a global cool-down that throttles failures and bootstrap but never a valid passkey. One-time bootstrap token, closed for good after enrolment. Revoke-all for sessions or for all access (fresh confirmation). Single-use recovery key, rate-limited, refused without an alert, shown once on the set-up screen. Browser sign-in uses WebAuthn with user verification. | `test_login.py`, `test_sessions.py`, `test_global_cool_down.py`, `test_routes.py`, `test_owner.py`, `test_vital.py`, `web/tests/admin-webauthn.test.ts`, `web/e2e/admin.spec.ts` (set-up, sign-in and sign-out with a virtual authenticator). | Done |
| A08 Software or Data Integrity Failures | Hash-pinned dependencies and actions. Audit log is an HMAC hash chain; the database blocks update, delete and truncate on it for every role, and the runtime login can only insert and read. Build provenance: phase 6. | `test_audit.py` (edit, removal, reorder, fork, rehash detected), `test_db_roles.py`, `test_audit_routes.py` (verify endpoint), CI installs with `--require-hashes` and `npm ci`. | Phase 1 done |
| A09 Logging and Alerting Failures | Sign-in, failure, lock-out, session, passkey and vital-action events go to the audit log, with no addresses, tokens or email. Content actions are audited with ids only, never the text. The audit page can show flagged security events only. Pluggable notifier tells the owner about lock-outs and vital actions; a vital action is refused if the notice cannot be sent. Logs to stdout only. Email alerts and log-based alerts: phase 5. | `test_login.py` (failures audited without personal data, lock-out notice), `test_vital.py`, `test_notify.py`, `test_audit_routes.py` (no secrets in the listing, flagged filter), `test_content.py` (no content in audit detail). | Phase 2A done |
| A10 Mishandling of Exceptional Conditions | Unknown routes return a plain 404. When the database or Redis is down every admin request gets the same plain 503 and no session is issued; public routes keep answering. Unexpected errors give a plain 500 with no trace. Notifier failure undoes the action it belongs to. The web proxy returns 503 when the API is missing or does not answer, and 413 for oversize bodies. Contact form and uploads: phases 2B, 4. | `test_fail_closed.py`, `test_public_availability.py`, `test_notify.py`, `test_status.py`. | Phase 1 done |
