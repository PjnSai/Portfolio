# OWASP Top 10 (2025) map

Each item maps to the control that covers it and the automated test that proves it. A row is **done** only when both exist and the test runs in CI. The 2021 list maps onto the same controls.

Status after phase 2C. "Phase 2A done" means the admin, auth and content-backbone part of the item is covered; later phases add the parts named in the row.

| Item | Control | Test | Status |
|------|---------|------|--------|
| A01 Broken Access Control | API denies by default; Django admin not installed. Every URL under `/api/v1/admin/` goes through one check (`core/authz.py`) with a declared level: Access only, session, or fresh passkey confirmation. A route with no level is refused. Cloudflare Access token checked on every admin request, before the URL is resolved, with the owner email compared exactly. One owner row in the database; the app login cannot add or remove it and no route creates an account. CSRF token on every state-changing session route, plus exact Origin and `Sec-Fetch-Site`. Random UUID keys. Content routes (sections, items, publish, versions, trash) need a session and are picked up by the route tests automatically; permanent delete only through the vital action, and only from the trash. Admin pages at `/desk` are `noindex`, `no-store` and not linked from the public site. The web service forwards only an allow-list of headers to the API. Media routes (library, upload, alt text, trash, restore, admin preview, cache status and retry) need a session and are picked up by the route tests. Public image route serves only images used by a published, shown section or the published settings; anything else is the same plain 404. | `test_routes.py` (every admin route, including the content routes, with no, wrong, expired, revoked and correct session; elevation), `test_content.py`, `test_vital.py` (trash-first permanent delete), `web/tests/api-proxy.test.ts`, `web/tests/security-headers.test.ts` (admin headers), `web/e2e/admin.spec.ts`, `test_csrf.py` (every route in the API with every state-changing method), `test_guard.py` (Access token, origin checks), `test_status.py`, `test_models.py` (UUID keys), `test_owner.py` (single owner, exact Access email), `test_db_roles.py` (owner and content grants), `test_media.py` (unpublished, hidden-section and trashed images not public), `test_routes.py` (media and cache routes). | Phase 2C done |
| A02 Security Misconfiguration | Debug off unless explicitly enabled; start-up refused without a secret key; admin refused if Access or the site origin is not configured. API headers defined once in `core/headers.py` (deny-all CSP, HSTS, `nosniff`, frame denial, no referrer). Web headers defined once in `web/lib/security-headers.ts` and written to the static export's `_headers` after each build: per-page CSP with script hashes, no nonce, no `unsafe-inline` or `unsafe-eval`; CI fails if the build produces server output (`web/scripts/check-export.ts`). Non-root read-only containers. Image hardening: phase 6. | `test_headers.py`, `test_status.py`, `test_guard.py` (missing configuration), `test_cors.py`, `web/tests/security-headers.test.ts`, `web/tests/pages-headers.test.ts`, `web/e2e/csp.spec.ts` (every inline script hashed, no nonce, injected script blocked in a real browser). | Phase 1 done |
| A03 Software Supply Chain Failures | npm lockfile, pip installs with hashes, actions pinned to commit hashes, `npm audit`, `pip-audit`, Dependabot, CodeQL. SBOM, image scan, provenance: phase 6. | CI jobs `web`, `api`, `images`; CodeQL workflow. | Started |
| A04 Cryptographic Failures | No passwords anywhere: passkeys only, public key stored. Session token is 256 random bits and only its SHA-256 is stored. Cookie is `__Host-`, `Secure`, `HttpOnly`, `SameSite=Strict`. Audit chain and rate-limit keys use HMAC-SHA-256 with keys from the environment. Access tokens accepted as RS256 only. HSTS on both services. TLS and Secret Manager: phase 7. Every image is decoded and drawn again as WebP from its pixels, so EXIF, GPS, XMP and trailing data are not kept; only the re-encoded sizes are stored. The Cloudflare token can purge cache only. | `test_sessions.py` (cookie flags, token size, hash only), `test_login.py` (public key material only), `test_guard.py` (unsigned and wrongly signed tokens), `test_audit.py` (rehash without the key is detected), `test_models.py` (no password table), `test_media.py` (EXIF and GPS removed, rotation applied first), Playwright upload test (no camera make in the public file). | Phase 1 done |
| A05 Injection | ORM only; CI and a test fail on `raw()`, `extra()` and direct cursors. Query and body fields are validated against fixed patterns and allow-lists before use. Content bodies go through strict DRF serializers, one shape per section type, item type and site settings: unknown fields refused (mass assignment), types, lengths and list sizes enforced, control characters refused, links `https` only, colours `#RRGGBB` only, stored upper case (no CSS from the admin; `url()`, `var()`, named colours and injection strings refused). The same shapes in zod give errors in the admin form; the API decides. Text is stored as typed and returned only as JSON with `nosniff`. Markdown is turned into React elements from an allow-list (`web/lib/markdown.ts`): raw HTML shows as text, images become alt text, links only `https`, `/` or `#`; no HTML string and no `innerHTML`. Uploads: the bytes decide the type (Pillow opens JPEG, PNG and WebP only; the file name and declared type are ignored), SVG and every other format refused, 8 MB and 40-megapixel caps, one file and the alt field only, alt text required. File names are 128 random bits plus a width; storage keys must match one pattern and local paths must stay in the store root, so path traversal has nothing to work with. | `test_injection.py`, `test_audit_routes.py`, `test_content_validation.py`, `test_content_limits.py` (every text field and list walked from the serializers: at the limit kept, over it refused), `test_stored_xss.py` (script payloads in every field of every shape, stored verbatim, JSON only; script and non-https links refused), `test_palettes.py` (colour format, unknown fields on palettes), `web/tests/markdown.test.ts` (30 XSS payloads, link schemes), `web/tests/admin-schemas.test.ts`, Playwright "script payloads in every project field stay plain text", CI step "No raw SQL", `test_media.py` (script, shell script, SVG, PDF and fake JPEG renamed as images; declared type ignored; oversize file and body; pixel cap; alt text required; unknown fields; ten path traversal forms on the public route; storage refuses keys outside the pattern), `test_storage.py`, `web/tests/admin-media.test.ts`, Playwright "media upload refuses a script and keeps no camera details". | Phase 2C done |
| A06 Insecure Design | Threat model kept current; security tests written before the code. Vital actions (adding a passkey, permanent deletion) need a fresh passkey confirmation, a fixed 24-hour wait, a notice to the owner and a second confirmation; a session alone can cancel but never run one. Undo instead of warnings: trash with 30-day restore, and version history with restore. Caps on sections and items. Publishing text that looks like it holds an email address, phone number or postcode is refused until the owner confirms (checked by the API, so the admin cannot skip it). Palette colours that fail WCAG AA contrast in light or dark are refused, and the error names the pair, mode and ratio; presets cannot be changed, at most 12 custom palettes, the default palette cannot be deleted. Admin fails closed. Public pages fail static: phase 3. Body size limits per route in the API guard and the web proxy (1 MB; the upload route alone takes one image). Daily upload cap. | `test_vital.py`, `test_notify.py`, `test_fail_closed.py`, `test_content.py` (trash, restore, purge, caps), `test_privacy_check.py`, `test_palettes.py`, `test_palette_migration.py`, `web/e2e/admin.spec.ts` (vital action with cancel, publish warning), `docs/THREAT-MODEL.md` review in the release checklist, `test_media.py` (daily cap, other routes keep 1 MB), `web/tests/admin-media.test.ts` (proxy limit). | Phase 2B done |
| A07 Authentication Failures | Passkey (user verification required) behind Cloudflare Access. Single-use challenges bound to their purpose and session. Server-side sessions: new token at sign-in and at every privilege change, 15-minute idle and 8-hour absolute timeout, revoke-all. Every failed sign-in costs the same work and returns the same answer. Cool-down after repeated failures per client; a global cool-down that throttles failures and bootstrap but never a valid passkey. One-time bootstrap token, closed for good after enrolment. Revoke-all for sessions or for all access (fresh confirmation). Single-use recovery key, rate-limited, refused without an alert, shown once on the set-up screen. Browser sign-in uses WebAuthn with user verification. | `test_login.py`, `test_sessions.py`, `test_global_cool_down.py`, `test_routes.py`, `test_owner.py`, `test_vital.py`, `web/tests/admin-webauthn.test.ts`, `web/e2e/admin.spec.ts` (set-up, sign-in and sign-out with a virtual authenticator). | Done |
| A08 Software or Data Integrity Failures | Hash-pinned dependencies and actions. Audit log is an HMAC hash chain; the database blocks update, delete and truncate on it for every role, and the runtime login can only insert and read. Build provenance: phase 6. | `test_audit.py` (edit, removal, reorder, fork, rehash detected), `test_db_roles.py`, `test_audit_routes.py` (verify endpoint), CI installs with `--require-hashes` and `npm ci`. | Phase 1 done |
| A09 Logging and Alerting Failures | Sign-in, failure, lock-out, session, passkey and vital-action events go to the audit log, with no addresses, tokens or email. Content actions are audited with ids only, never the text. The audit page can show flagged security events only. Pluggable notifier tells the owner about lock-outs and vital actions; a vital action is refused if the notice cannot be sent. Logs to stdout only. Email alerts and log-based alerts: phase 5. Media and cache purge events are audited; a failed purge is logged and shown in the admin until a purge works. | `test_login.py` (failures audited without personal data, lock-out notice), `test_vital.py`, `test_notify.py`, `test_audit_routes.py` (no secrets in the listing, flagged filter), `test_content.py` (no content in audit detail), `test_purge.py`. | Phase 2A done |
| A10 Mishandling of Exceptional Conditions | Unknown routes return a plain 404. When the database or Redis is down every admin request gets the same plain 503 and no session is issued; public routes keep answering. Unexpected errors give a plain 500 with no trace. Notifier failure undoes the action it belongs to. The web proxy returns 503 when the API is missing or does not answer, and 413 for oversize bodies. Contact form: phase 4. A failed cache purge never undoes a publish; it is kept on the settings row and shown with a retry button. Storage failure on upload removes what was stored and returns 503. The public site document may be served stale by the edge if the API cannot answer (`stale-if-error`). | `test_fail_closed.py`, `test_public_availability.py`, `test_notify.py`, `test_status.py`, `test_purge.py` (failed and crashing purger, retry, later purge clears the report), `test_media.py` (storage failure fails closed). | Phase 2C done |
